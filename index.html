1. What is OpenAPI?

OpenAPI (formerly Swagger) is a vendor-neutral, language-agnostic standard for describing HTTP APIs in a machine-readable YAML or JSON file. Because the description is data, one file can drive documentation, client SDKs, mock servers, tests and validation.

openapi

The spec version (here 3.1.0), which also aligns schemas with JSON Schema.

info

Title, version, description (Markdown), contact and license.

servers

Base URLs where the API lives, e.g. https://catfact.ninja.

tags

Groups of operations; Scalar uses them as sidebar sections.

paths

Each path holds HTTP methods; each operation has an operationId, parameters and responses by status code.

components

Reusable schemas, parameters, responses and security schemes, reached with $ref.

openapi: 3.1.0
info:        { title: Cat Facts API, version: 1.0.0 }
servers:     [ { url: https://catfact.ninja } ]
paths:
  /fact:
    get:
      operationId: getRandomFact
      parameters: [ { name: max_length, in: query, schema: { type: integer } } ]
      responses:
        "200":
          content:
            application/json:
              schema: { $ref: "#/components/schemas/Fact" }   # reuse
components:
  schemas:
    Fact: { type: object, properties: { fact: {type: string}, length: {type: integer} } }

2. How is Scalar put together?

Scalar is an open-source (MIT) toolkit. The part used here is @scalar/api-reference, a Vue-based front-end app shipped as a single JavaScript bundle. It runs entirely in the browser.

openapi.yamlsource of truth
→
Fetch & parseYAML/JSON loaded from url
→
Resolve & normalize$refs dereferenced, spec upgraded to a common shape
→
Vue componentssidebar, operations, schemas, code samples
→
Reference page+ embedded API client

Spec → page

Scalar loads the document, resolves $ref links and walks the tree: tags become sidebar groups, each path+method becomes an operation card, schemas become property tables with types and examples.

Code samples

For every operation it generates request snippets (cURL, JavaScript, Python and more) from the parameters and server URL, so they stay in sync with the spec.

Config object

Behaviour and looks are set by one configuration object: url, theme, layout, dark mode, default client and so on.

Package split

Reference renderer (@scalar/api-reference), API client (@scalar/api-client), plus framework integrations (Express, Fastify, Hono, FastAPI, Django, .NET and others) that serve the same bundle.

3. How is Scalar embedded?

Two main routes. Both share the same configuration object.

A. CDN script (used here)

Zero tooling: add the script tag, call Scalar.createApiReference.

B. npm / framework

npm i @scalar/api-reference then import { createApiReference }, or use an integration that mounts the docs at e.g. /reference in your server.

<div id="app"></div>
<script src="https://cdn.jsdelivr.net/npm/@scalar/api-reference"></script>
<script>
  Scalar.createApiReference('#app', { url: './openapi.yaml', theme: 'purple' })
</script>

Tip: pin a version (@scalar/api-reference@1.28.5) so an upstream release cannot change your docs unexpectedly.

4. The built-in API client

Every endpoint in the reference has a Test Request button that opens Scalar's API client, a Postman-style panel inside the docs.

Pre-filled from the spec

Server, method, path, query parameters (with their examples such as limit=5) and headers are filled in automatically.

Send & inspect

Edit values, press Send, and see status, timing, headers and the formatted JSON body without leaving the page.

CORS & proxy

Requests are made from the browser. If an API blocks CORS, Scalar's optional proxyUrl can relay them. Cat Facts allows browser calls.

Demo walkthrough (for your screenshots)

  1. Open docs.html, choose Facts → List cat facts.
  2. Click Test Request, set limit = 3 and max_length = 100.
  3. Press Send: the response shows data[] of facts plus pagination fields, matching the FactPage schema.
  4. Switch the code sample from cURL to JavaScript to show generated snippets.

Run it

Scalar fetches openapi.yaml with the browser, so serve the folder over HTTP (opening the file directly can be blocked).

cd scalar-cat-facts-docs
python -m http.server 8000
# open http://localhost:8000  and  http://localhost:8000/docs.html

To validate the spec: npx @redocly/cli lint openapi.yaml
